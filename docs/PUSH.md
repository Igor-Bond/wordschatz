# Уведомление на закрытое приложение

Что сделано, что осталось сделать вам и чего от этого ждать.

## Почему нельзя было проще

Разбудить закрытое приложение веб не умеет. `setTimeout` живёт ровно
столько, сколько живёт вкладка; расписание уведомлений в браузере
(`TimestampTrigger`) было опытной функцией Chrome и убрано; периодическая
фоновая синхронизация есть только в Chrome на Android, интервал выбирает
браузер, и в назначенный час она не попадает.

Остаётся Web Push: устройство подписывается, а кто-то снаружи раз в сутки
шлёт сообщение. «Кто-то снаружи» здесь — расписание GitHub Actions: для
публичного репозитория оно бесплатно, и своего сервера не появляется.
Node нужен только на машине сборщика, у вас его по-прежнему нет.

Firebase Cloud Messaging не спасает: сообщения бесплатны, но отправлять
их должен доверенный код, а Cloud Functions требуют платного тарифа.

## Как это устроено

```
приложение → подписка → Firestore: users/{uid}/pushSubscriptions/{id}
                                          ↑
                      раз в сутки: GitHub Actions → tools/send-push.mjs
                                          ↓
                          push-служба браузера → sw.js → уведомление
```

- `js/core/push.js` — подписка, отписка, запись в облако;
- `sw.js` — обработчики `push` и `notificationclick`;
- `tools/send-push.mjs` — отправитель, запускается на машине GitHub;
- `.github/workflows/reminder.yml` — расписание.

Кнопка живёт в «Профиль → Статистика», под блоком облака. Она
показывается только после входа через Google: подписка хранится в вашем
облаке, без входа её некуда положить.

## Что нужно сделать вам

Четыре вставки в настройках репозитория, все — копирование готовой
строки. Добавить их за вас я не могу и не должен: это распоряжение
вашими учётными данными.

GitHub → репозиторий `wordschatz` → **Settings** → **Secrets and
variables** → **Actions**.

### Вкладка Secrets, кнопка New repository secret

| Имя | Значение |
|---|---|
| `VAPID_PRIVATE_KEY` | строка из файла `vapid-private.key` в корне проекта |
| `PUSH_SUBSCRIPTIONS` | нажмите «Скопировать» в профиле приложения и вставьте |

Пара ключей уже создана, файл `vapid-private.key` в `.gitignore` и в
репозиторий не уедет. После вставки его можно удалить.

Подписку даёт само приложение: «Профиль → Статистика → Уведомление на
закрытое приложение → СКОПИРОВАТЬ». Кнопка кладёт в буфер строку вида
`{"endpoint":"https://fcm.googleapis.com/…","keys":{…}}` — её и вставить.
Если буфер обмена недоступен, строка покажется на экране для выделения
руками.

### Вкладка Variables, кнопка New repository variable

Это не секреты, они видны всем — так и задумано протоколом.

| Имя | Значение |
|---|---|
| `VAPID_PUBLIC_KEY` | `BBGaQF_P-_yo-vyW6hwsltlkwQlUAxUt0JMcJRZyP0wIO5PNhqZfexX4pK2IEe_JPHCvS0FcXSHsIsXrTKxpuPU` |
| `VAPID_SUBJECT` | `mailto:` и ваша почта |

### Если устройств несколько

Тогда вместо `PUSH_SUBSCRIPTIONS` можно завести
`FIREBASE_SERVICE_ACCOUNT` — консоль Firebase → Project settings →
Service accounts → Generate new private key, и содержимое скачанного
JSON целиком. Отправитель тогда сам заберёт подписки всех устройств из
Firestore, куда приложение и так пишет, и сам вычистит протухшие.

Путь сложнее, и нужен он ровно тогда, когда вставлять подписку с каждого
нового устройства надоест. С одним телефоном проще первый.

## Как проверить

1. Откройте приложение, войдите через Google, включите уведомление в
   «Профиль → Статистика». Там же появится кнопка «Проверить подписку»:
   она читает запись обратно из облака и показывает службу и время. Если
   написала, что подписка в облаке, — сторона приложения сделана, дальше
   дело за секретами и расписанием.
2. GitHub → Actions → «Напоминание о занятии» → **Run workflow**.
3. В журнале запуска будет строка вида
   `Источник: секрет PUSH_SUBSCRIPTIONS. Подписок: 1.` и следом
   `Отправлено: 1. Протухших: 0, из них убрано: 0.`

Если написано «Подписок нет» — приложение не подписалось: проверьте, что
вход выполнен и разрешение на уведомления выдано.

## Чего ждать честно

- **Android** (Chrome, Firefox, Edge) — приходит на закрытое приложение.
- **iPhone** — только если приложение добавлено на домашний экран
  (с iOS 16.4). В браузере не приходит.
- **Компьютер** — пока запущен браузер, даже без открытой вкладки.
- **Точность.** Расписание GitHub идёт по UTC и в часы нагрузки
  опаздывает на пять–двадцать минут, иногда пропускает запуск. Это
  напоминание, а не будильник.
- **Перевод часов** cron не знает: `0 17 * * *` — это 19:00 по Киеву
  летом и 18:00 зимой. Сдвиг правится руками в `reminder.yml`.
- **Шестьдесят дней.** GitHub отключает расписания в публичном
  репозитории после двух месяцев без коммитов. Если напоминания пропали —
  сначала смотреть сюда.

## Что проверено, а что нет

Проверено: пара ключей сходится (подпись закрытым проверяется открытым),
подписка собирается и кладётся в облако по устойчивому ключу, кнопка
«Скопировать» отдаёт её строкой и при недоступном буфере показывает для
выделения руками, обработчики в service worker на месте. Отправитель
прогнан на подставных данных по обоим путям: одна подписка, массив
подписок, битый JSON, отсутствующий ключ, отсутствие обоих источников —
шлёт живым, отмечает протухшие (404 и 410), пропускает неполные,
без секретов выходит с понятной ошибкой.

Не проверено: настоящая доставка. Для неё нужны секреты в вашем
репозитории, и первый живой запуск — за вами.
