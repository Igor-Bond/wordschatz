# Тестирование и аудит

Итоговая проверка версии 2.1 (кэш v70), 24 августа 2026. Первый аудит
лежит в `AUDIT.md` и относится к версии 1.7 — с тех пор изменилось
многое, поэтому проверка проведена заново и целиком.

Что подменялось: только генерация набора слов языковой моделью. Ключа
Gemini у меня нет и быть не должно. Всё остальное работало по-настоящему,
включая сетевые запросы к Wiktionary.

## 3. Оценка по современным меркам

### Пирамида проверок

Основание есть и оно живое: 174 проверки на чистой логике, прогоняются
одной командой без Node и без сети. Они уже поймали четыре настоящих
ошибки — правило выпадения `e` (`teuer → teuerer`), пропущенное `-n` в
дательном множественного, видовую пару «убирать/убрать» и двойной зачёт
ответа в сборке предложения.

Чего не хватает по современной практике: **среднего слоя**. Нет ни одной
проверки, которая проходит сценарий целиком — «сгенерировал набор,
прошёл урок, получил XP». Такие проверки ловят то, что не видно ни
модульным, ни ручным взглядом: сломанную связку между двумя верными
частями. Сегодня эту роль выполняю я вручную, и это не масштабируется.

Покрыто 12 модулей из 49. Непокрытое — это отрисовка (её сложно
проверять без браузерного драйвера) и `ai.js` (нужен ключ). Из
рискованного непокрытым остался `core/scheduler.js` — дневной план,
ради которого приложение открывают.

### Доступность

Слабое место, и оно не изменилось. На главном экране 14 кнопок, у трёх
нет ни текста, ни подписи; во всём документе один `aria-label` и ноль
`aria-live`. Значит:

- экранный чтец не объявит смену экрана и результат ответа;
- три кнопки прочитаются как «кнопка» без пояснения;
- клавиатурная навигация работает (стиль фокуса есть), но порядок обхода
  никто не проверял.

По WCAG это уровень «не проходит A» — не из-за контраста или размеров,
с ними как раз хорошо, а из-за отсутствия ролей и объявлений. Для
личного инструмента это допустимо; называть его доступным нельзя.

### Производительность

290 КБ по сети и 146 мс до готовности DOM — хороший результат, особенно
после отказа от компилятора Tailwind в браузере. Узкие места убраны там,
где они были заметны: словарь рисуется порциями, поиск ждёт паузы в
наборе, снимок ужимается перед отправкой.

Что осталось: код не минифицируется и не делится на части. 675 КБ
собственного JS разбираются целиком при каждом холодном старте, включая
модули, которые в этом сеансе не понадобятся. Пока это 146 мс и
незаметно; при удвоении кода станет заметно.

### Безопасность и приватность

| Что | Состояние |
|---|---|
| Ключ ИИ в разметке | Нет |
| Ключ в резервной копии | Нет |
| Ключ на экране настроек | Скрыт, показывается по кнопке |
| Подстановка содержимого в код обработчика | 4 места, все с фиксированными значениями |
| Правила Firestore | Доступ только к своим данным по uid |
| Данные пользователя | Только на устройстве и в его облаке |

Класс ошибок с подстановкой в код закрыт: данные лежат в
`data`-атрибутах, где апостроф — обычный символ. Оставшиеся четыре
подстановки передают перечисления (`de`/`ru`, части речи, статусы), где
апострофа быть не может.

### Пользовательский опыт

Что сделано хорошо:

- **Приложение объясняет себя.** Раздел «Информация» показывает версию,
  кэш, объём данных, найденный голос; есть проверка подключения к ИИ,
  полнота карточек, сводка сверки. Разбирать «не работает» с телефона
  без этого пришлось бы гаданием.
- **Отказы понятны.** Недействительный ключ называется недействительным
  ключом, а не «ошибкой сети». Напоминание честно пишет, чего не умеет.
  Сверка молчит там, где не уверена.
- **Выбор оставлен человеку** там, где решение не однозначно:
  полноэкранный режим против часов на экране, слияние против замены при
  импорте, подозрение в переводе вместо автоисправления.

Что остаётся неудобным:

- **Нельзя вернуться назад** в первом запуске. Опечатку в имени теперь
  можно поправить в настройках, но сам мастер идёт только вперёд.
- **Смена языка** не трогает уже сохранённые переводы. Предупреждение
  есть, решения нет — словарь после переключения будет смешанным.
- **Белая полоса снизу на Android** — системная панель жестов. Из веба
  не красится; убирается только полноэкранным режимом, вместе с часами.
  Это ограничение платформы, а не недоработка.

### Методика обучения

Оценки не изменились с `REVIEW.md`, повторю коротко: слова не взвешены
по частотности, устной речи нет, грамматика остаётся на уровне слова.
Приложение хорошо учит узнавать и писать; говорить оно не учит.

Зато закрыта главная опасность такого приложения — **уверенное обучение
неправильному**. Формы сверяются с Wiktionary, перевод сверяется и
помечается подозрением, спорные случаи не трогаются вовсе.

## 4. Заключение

Приложение готово к ежедневному использованию. Оно проходится насквозь
без единой ошибки в консоли, делает всё заявленное, честно ведёт себя
при отказах и объясняет своё состояние. Сорок с лишним модулей и
174 проверки для проекта, написанного под одного человека, — это выше
обычной планки.

Три вещи, которые я бы делал дальше, по убыванию пользы:

1. **Сквозные проверки на один-два сценария.** Сегодня связки между
   модулями проверяю только я и только руками. Это единственный пробел,
   который со временем будет дорожать.
2. **Доступность до разумного минимума.** Подписи трём кнопкам,
   `aria-live` на результат ответа, проверка порядка обхода. День работы,
   и приложением можно будет пользоваться не только глазами.
3. **Частотность слов.** Самое дорогое по трудоёмкости и самое ценное
   для результата: набор, взвешенный по частоте, учит быстрее любого
   тренажёра заданий.

Не сделано и не планируется без отдельного решения: доставка push (ждёт
трёх значений в секретах репозитория, см. `PUSH.md`), минификация и
разделение кода, хранение переводов по языкам.
