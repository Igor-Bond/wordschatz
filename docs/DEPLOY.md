# Размещение приложения

Приложение — чистая статика: ни сборки, ни серверного кода. База лежит
в IndexedDB браузера, синхронизация идёт напрямую в Firebase. Значит,
подойдёт любой хостинг статических файлов, и платить за это не нужно.

## Почему уходим с Netlify

Бесплатный план Netlify — 300 кредитов в месяц, жёсткий лимит. Когда они
кончаются, сначала останавливаются деплои, а затем и раздача сайта:
посетители видят «Site not available». Для проекта, который должен быть
бесплатным всегда, это неподходящее условие.

GitHub Pages для публичных репозиториев бесплатен без счётчика кредитов.

## Вариант 1. Адрес вида `igor-bond.github.io/wordschatz/`

Ничего создавать не нужно, репозиторий уже на месте.

**Репозиторий должен быть публичным.** На бесплатном плане GitHub Pages
работает только с публичными репозиториями; для приватных нужен платный
план. В коде нет ничего секретного:

- ключи Gemini хранятся в браузере пользователя (`localStorage`) и в
  репозиторий не попадают — проверено и по рабочему дереву, и по всей
  истории коммитов;
- `js/firebase.config.js` содержит веб-конфигурацию Firebase, а она по
  замыслу Google встраивается в клиентский код: любой посетитель сайта
  видит её и сейчас, открыв исходники страницы.

Данные защищают правила Firestore, а не секретность репозитория. Перед тем
как открывать код, стоит сверить их с эталоном в `docs/firestore.rules`:
доступ разрешён только к своей ветке `users/{uid}`, всё остальное закрыто.

1. Сделать репозиторий публичным:
   `https://github.com/Igor-Bond/wordschatz/settings` → внизу
   **Danger Zone** → **Change repository visibility** → **Make public**
2. Открыть `https://github.com/Igor-Bond/wordschatz/settings/pages`
3. **Source** → **Deploy from a branch**
4. **Branch** → `main`, папка `/ (root)` → **Save**
5. Через одну-две минуты сайт будет по адресу
   `https://igor-bond.github.io/wordschatz/`

## Вариант 2. Адрес вида `имя.github.io`

Корневой адрес выдаётся только под имя аккаунта или организации: репозиторий
должен называться ровно `<имя>.github.io`. Имя `wortschatz` на GitHub уже
занято другим человеком, поэтому нужен свободный вариант —
например `wortschatz-app` или `wortschatz-pro` (на момент проверки свободны).

1. Создать бесплатную организацию с выбранным именем:
   `https://github.com/organizations/plan` → **Free**
2. Перенести туда репозиторий: **Settings → General → Transfer ownership**
3. Переименовать репозиторий в `<имя>.github.io`
4. Включить Pages так же, как в варианте 1
5. Сайт будет по адресу `https://<имя>.github.io/`

## После включения Pages — обязательный шаг

Вход через Google работает только с разрешённых доменов, иначе Firebase
вернёт `auth/unauthorized-domain`.

1. Открыть
   `https://console.firebase.google.com/project/wortschatz-f1ca2/authentication/settings`
2. **Authorized domains** → **Add domain**
3. Добавить домен новой площадки, например `igor-bond.github.io`

`localhost` там уже есть, локальную разработку это не ломает.

## Что учтено в коде

- Все пути относительные, поэтому приложение одинаково работает и в корне
  домена, и в подпапке вида `/wordschatz/`. Проверено локально.
- `manifest.json`: `id`, `start_url` и `scope` заданы как `./` — с абсолютным
  `/` установленное приложение считало бы своим корень домена, а не подпапку.
- `.nojekyll` в корне: без него GitHub Pages прогоняет содержимое через Jekyll
  и пропускает файлы и папки, начинающиеся с подчёркивания.
- Dexie вендорится как `dexie.min.js`, а не `.mjs`: не всякий хостинг отдаёт
  `.mjs` с правильным Content-Type, а при неверном типе импорт модуля падает
  и приложение не запускается вовсе.
- `netlify.toml` оставлен на случай возврата: GitHub Pages его не читает.

## Сборка стилей

Стили Tailwind собираются заранее в `css/tailwind.css`. До этого их
генерировал Play CDN — компилятор Tailwind весом 441 КБ, работавший
в браузере при каждом запуске приложения ради примерно пятнадцати
килобайт готового CSS.

Node для этого не нужен: у Tailwind есть автономный исполняемый файл.

1. Скачать один раз и сохранить как `tools\tailwindcss.exe`:

   ```
   Invoke-WebRequest -Uri "https://github.com/tailwindlabs/tailwindcss/releases/download/v3.4.17/tailwindcss-windows-x64.exe" -OutFile ".\tools\tailwindcss.exe"
   ```

   Сам файл в репозиторий не попадает, он в `.gitignore`.

2. Собрать:

   ```
   powershell -ExecutionPolicy Bypass -File .\tools\build-css.ps1
   ```

   Для разработки удобен режим слежения: тот же скрипт с `-Watch`.

3. **Результат нужно закоммитить.** Сборки на стороне GitHub Pages нет,
   поэтому `css/tailwind.css` едет в репозиторий как обычный файл.

Пересобирать нужно после появления в разметке новых классов Tailwind.
Забыли — класс не применится, это видно сразу.

Пока `css/tailwind.css` отсутствует, `index.html` включает прежний
компилятор в браузере и пишет предупреждение в консоль: приложение не
должно остаться без стилей из-за невыполненной команды.

### Классы, собираемые из кусков

Сканер Tailwind читает исходники и ищет в них строки целиком, а Play CDN
смотрел на живой DOM и видел любые классы. Шесть мест в коде собирают класс
подстановкой — `text-${accent}`, `bg-${stepColor}/10` и подобные. Такие
классы перечислены в `safelist` в `tailwind.config.js`; при добавлении
нового цвета шапки его нужно дописать туда же.

## Обновление после переезда

Push в `main` — и через минуту-две новая версия на месте. Приложение само
покажет баннер обновления: service worker увидит новую версию кэша
(`APP_VERSION` в `sw.js`) и предложит перезагрузиться.
